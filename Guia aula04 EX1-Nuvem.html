Criando e executando uma aplicação Java 21 dentro de um container Docker.

Pasta: C:\Users\Instrutor\Aula04_EX1_Nuvem Terminal: PowerShell (Windows) Imagem base: eclipse-temurin:21-jdk

0 O que vamos fazer

O objetivo é empacotar um programa Java em uma imagem Docker e executá-lo em um container, sem precisar instalar o Java na máquina — o Java já vem dentro da imagem.

ArquivoFunção
Main.javaCódigo-fonte Java que imprime mensagens no terminal.
DockerfileReceita que ensina o Docker a montar a imagem: copiar, compilar e executar.
Imagem é o "molde" (o pacote pronto, salvo em disco). Container é o molde em execução. De uma imagem você pode criar vários containers.

1 Abrir o terminal na pasta do projeto

Abra o PowerShell e navegue até a pasta do exercício:

cd C:\Users\Instrutor\Aula04_EX1_Nuvem

Confirme que os dois arquivos estão presentes:

ls

Devem aparecer Dockerfile e Main.java.

Atenção: se você não estiver dentro dessa pasta, o comando docker build vai falhar com erro de arquivo não encontrado.

2 Verificar se o Docker está funcionando

Confira a versão instalada:

docker --version

E se o serviço (daemon) está no ar:

docker info
Se aparecer "cannot connect to the Docker daemon" ou "error during connect", abra o Docker Desktop, aguarde o ícone da baleia ficar verde/estável e rode docker info novamente.

3 Entender o Dockerfile

# Imagem base: já vem com o JDK 21 instalado
FROM eclipse-temurin:21-jdk

# Diretório de trabalho dentro do container
WORKDIR /app

# Copia Main.java da máquina local para /app no container
COPY Main.java .

# Compila o código durante a CRIAÇÃO da imagem (gera Main.class)
RUN javac Main.java

# Comando executado quando o container é iniciado
CMD ["java", "Main"]
InstruçãoQuando rodaO que faz
FROMbuildDefine a imagem base (sistema + JDK 21).
WORKDIRbuildCria e entra na pasta /app.
COPYbuildLeva o arquivo do seu PC para dentro da imagem.
RUNbuildExecuta a compilação e grava o resultado na imagem.
CMDrunComando padrão ao iniciar o container.

4 Construir a imagem

docker build -t aula04-java .
  • -t aula04-java — dá um nome (tag) à imagem.
  • . — o ponto final indica o contexto de build: a pasta atual. Ele é obrigatório e esquecê-lo é o erro mais comum.

Durante o build você verá as etapas [1/4] FROM, [2/4] WORKDIR, [3/4] COPY, [4/4] RUN javac. Ao final:

=> naming to docker.io/library/aula04-java
Na primeira execução o download da imagem base (~300 MB) pode demorar. Nas próximas vezes o Docker reaproveita o cache e o build é quase instantâneo.

5 Conferir se a imagem foi criada

docker images

A imagem aula04-java deve aparecer na lista, com a tag latest.

6 Executar o container

docker run --rm aula04-java

--rm remove o container automaticamente ao terminar, evitando acúmulo de containers parados na máquina.

7 Alterou o código? Refaça o build

O Java é compilado durante o build. Então, ao editar o Main.java, a imagem antiga continua com o código velho. Rode os dois comandos na ordem:

docker build -t aula04-java .
docker run --rm aula04-java

Se quiser forçar tudo do zero, ignorando o cache:

docker build --no-cache -t aula04-java .
